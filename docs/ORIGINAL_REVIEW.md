# Original Coursework Review

이 문서는 보존된 2023년 제출 자료에서 확인된 사실과 2026년 재구현을 구분합니다.
당시의 기억이나 의도는 코드·보고서·실행 증거로 확인되지 않으면 추정하지 않습니다.

## 확인된 2023년 구현

### 기초 socket과 멀티서비스

- AF_UNIX `SOCK_STREAM` 서버·클라이언트
- AF_INET 동기형 1:1 채팅
- 시간 조회, 파일 다운로드, Echo 메뉴를 제공하는 TCP 멀티서비스 시도
- 서비스별 실행 화면 존재

### 비동기 1:1 채팅

- 입력 프로세스와 표시·통신 프로세스를 AF_UNIX socket으로 분리
- 두 호스트 사이를 AF_INET socket으로 연결
- nonblocking receive를 사용해 양쪽이 독립적으로 메시지를 입력
- 네 개 터미널을 이용한 지정 시나리오 실행 화면 존재

### 동시 클라이언트 처리

- `fork()`로 클라이언트별 자식 프로세스를 생성하는 Echo 서버
- `select()`로 세 클라이언트의 입력을 감시하는 서버
- 여러 클라이언트의 접속·메시지 처리 실행 화면 존재

### 최종 로비·채팅방 과제

- Makefile 빌드, 서버 시작, 클라이언트 시작까지만 완료로 기록
- 대기실 이동, 방 목록, 방 입장·퇴장, 다중 채팅, 종료 절차는 미완료로 기록
- 코드도 단일 클라이언트 accept 이후 수신 출력 수준이므로 완성작으로 분류하지 않음

## 원본에서 확인된 제한사항

| 영역 | 확인된 상태 | 2026년 처리 |
|---|---|---|
| TCP 파일 전송 | 파일 뒤에 79바이트의 제어·메뉴 문자열 혼입 | 줄 단위 누적 buffer와 독립 테스트 |
| 멀티서비스 최신 소스 | 실행 파일 생성 뒤 수정되어 compile regression 발생 | 공개 코드로 사용하지 않음 |
| 상태 초기화 | 대입 대신 비교 연산자 사용 | 상태 전이를 새로 작성 |
| 비동기 처리 | nonblocking `recv` busy polling | `select` event loop로 변경 |
| fork Echo 종료 | `strcmp(...) == 10` 조건 | 공개 코드로 사용하지 않음 |
| disconnect | `recv()==0` 및 descriptor 제거 부족 | 즉시 방 이탈·socket 정리 |
| partial send | 한 번의 `send`가 전체를 보낸다고 가정 | `chat_send_all` 반복 처리 |
| signal 종료 | 자원 정리 경로 부족 | handler는 flag만 변경, main loop에서 정리 |

## 기여도와 저작권 원칙

- 제출 ZIP과 보존 폴더의 source hash가 일치하는 자료만 본인 제출 근거로 사용합니다.
- 강의 예시를 완성하는 형태였던 과제는 독자 설계로 과장하지 않습니다.
- 원본 코드는 로컬 비교용으로만 보관하고 공개 commit에서 제외합니다.
- 2026년 코드 재검토 과정에서 AI 기반 정적 분석을 보조적으로 활용했습니다. 발견 항목은
  과제 명세·실제 코드·보존 실행 결과를 직접 대조하고 독립 테스트로 검증합니다.
